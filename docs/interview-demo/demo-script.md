# CrowdLaunch AI：3 分钟面试演示脚本

## 0:00–0:25 业务问题

“海外众筹团队的难点不是缺一个聊天机器人，而是研究、Launch 准备、投放优化和 Backer 反馈分散在不同工具里，且每个建议都需要证据和人工判断。所以我做了一个面向 Kickstarter / Indiegogo 的 Agent 工作台。”

## 0:25–1:05 机会研究

打开「机会研究」，点击运行分析。

“Opportunity Agent 会读取目标市场、平台、竞品证据和回报档位成本。毛利由规则引擎计算，不交给模型猜。当前系统会给出机会评分、证据覆盖和 GO / ADJUST / STOP 建议，并明确显示警告。”

重点指出：回报档位价格、产品成本、物流、平台费率和毛利率。

## 1:05–1:35 Launch 计划

切换到「Launch 计划」。

“研究结果会进入 Launch 时间线、档位设计和本地化任务。这里把 AI 建议与人工审批拆开：系统可以生成计划，但上线前必须由运营确认。”

点击批准，指出这是内部审计状态，没有触发真实上线。

## 1:35–2:15 增长优化

切换到「增长优化」。

“Growth Agent 对 CPC、CVR 和 ROAS 做可解释诊断。例子里它发现一个广告组 CPC 上升且转化下降，因此建议把部分预算迁移给表现更好的广告组。”

点击批准建议，并强调页面与接口均显示 `external_action_executed: false`。

## 2:15–2:45 Backer Voice

切换到「Backer Voice」。

“Agent 将留言归类为物流、电池规格、配件兼容等主题，给出风险优先级并生成回复草稿。草稿不会自动发送，避免错误承诺或品牌风险。”

## 2:45–3:00 工程可信度

切换到「运行记录」。

“每次运行都会记录输入、输出、警告和审批。项目有 FastAPI、SQLite/PostgreSQL、自动化测试和可选模型增强；没有 Key 时使用确定性模式，保证演示稳定。下一步可以接入广告平台的只读数据，再逐步开放受控写入。”

## 常见追问

### 为什么不让大模型直接算毛利？

数值计算需要稳定、可复核。规则引擎负责计算，大模型只解释结果和生成文案，可以减少幻觉对业务决策的影响。

### 这是 Agent 还是普通 Dashboard？

Dashboard 是交互层。Agent 的核心是：接收目标与上下文、调用确定性工具、生成结构化建议、写入运行记录，并在高影响动作前进入人工审批。

### 目前接了真实平台吗？

没有。作品集使用合成数据，不伪装成真实客户案例。接口和数据模型已经为只读连接器预留，但真实接入需要客户授权、权限隔离和合规评审。

### 大模型失败怎么办？

模型适配器会回退到规则引擎结果。核心计算和审批链路不依赖模型在线。
